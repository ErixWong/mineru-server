# docs-260725-01-product-improvement-roadmap

## 背景

本任务记录一次从产品经理视角出发的项目分析。当前 mineru-server 已具备可运行的核心闭环：

- REST API / MCP Tools 异步提交、查询和下载交付物；
- Admin Console 支持登录、caller 管理、任务查看、任务创建、交付物预览和后处理方案；
- SQLite 本地队列、并发控制、任务取消、超时、重试和后处理 run；
- caller key 已进入加密存储与显式 reveal/copy 模型；
- 前后端一体化镜像与本地开发路径已经成形。

因此下一阶段重点不应是继续堆接口，而是围绕“好用、可观测、可配置、可交付、可治理”把产品体验补齐。

## 核心判断

项目已经越过技术 demo 阶段，正在接近一个可运营的 PDF 解析服务。现有架构里最有价值的资产是：

1. **统一任务模型**：REST、MCP 和管理台共享任务队列与 TaskService。
2. **交付物模型**：Markdown、JSON、图片和后处理结果已经纳入统一 deliverables。
3. **多调用方隔离**：caller 与 owner 绑定，为后续租户治理、配额和审计打下基础。
4. **后处理流水线**：Action / Plan / Run 三层模型已经具备产品化潜力。
5. **Admin SPA**：管理台已经从旧 HTML 迁移到 Vue SPA，适合继续建设运营工作台。

主要短板集中在管理台产品化和运营可观测性：

- Dashboard 仍是欢迎页，无法快速判断系统健康；
- 任务筛选偏工程字段，不够符合管理员日常排障；
- 任务详情缺少诊断信息、耗时拆解和错误归因；
- 交付物下载与预览还未形成完整工作台；
- caller 管理缺少配额、权限范围、审计和趋势；
- 后处理方案缺少模板、试运行和版本治理；
- 文档首屏体验仍受 Windows 默认编码影响，中文 README 可能显示乱码。

## 产品优化目标

### P0：可观测管理台

让管理员打开控制台后能立刻回答：

- 服务是否健康？
- 当前队列是否积压？
- 最近任务成功率如何？
- 哪些任务失败，需要处理？
- 默认 backend / VLM / 后处理 LLM 配置是否可用？
- 是否存在默认密码、缺少安全配置等风险？

### P1：任务诊断与交付物工作台

让任务详情页不仅能“看结果”，还要能“定位问题”和“拿走结果”：

- 展示任务请求参数、排队耗时、解析耗时、后处理耗时；
- 对失败任务显示错误分类和建议动作；
- 支持带参数修改的复跑；
- 支持 zip 下载全部交付物；
- 支持 Markdown / JSON / 图片画廊的分组预览；
- 支持复制 REST/MCP 调用和下载示例。

### P2：调用方治理

把 caller 从 API key 管理升级为轻量租户管理：

- caller 级任务量、成功率、失败率、平均耗时；
- daily/monthly quota；
- 最大文件大小、最大页数、允许 backend 白名单；
- key reveal/reset/disable/delete 审计；
- caller 详情页展示最近任务和错误趋势。

### P3：后处理产品化

把后处理从高级配置变成可复用能力：

- 内置模板：标题优化、摘要生成、合同条款提取、表格说明、章节重排；
- prompt 试运行；
- Plan 草稿 / 发布 / 版本历史；
- Plan 被 caller 默认引用时的影响提示；
- 批量对历史任务重跑某个 Plan。

## 建议路线

| 阶段 | 名称 | 目标 | 典型交付 |
|---|---|---|---|
| V1.1 | 可观测管理台 | 让管理员知道系统是否正常 | Dashboard、健康诊断、失败任务入口 |
| V1.2 | 交付物工作台 | 让解析结果更容易预览和下载 | zip 下载、图片画廊、结果分组、代码片段 |
| V1.3 | 多调用方治理 | 让 caller 可运营、可限流、可审计 | 配额、backend 白名单、caller 详情、审计日志 |
| V1.4 | 后处理产品化 | 让后处理成为产品差异化能力 | 模板、试运行、版本管理、批量重跑 |

## 重构原则

本轮不建议为了“看起来更清爽”做大拆分。重构应跟随产品能力自然发生：

1. Dashboard 需要指标时，抽 `AdminMetricsService`；
2. 任务列表和详情需要统一展示口径时，抽 `AdminTaskViewService`；
3. caller 进入配额和审计后，抽 `CallerGovernanceService`；
4. 后处理支持模板、版本和试运行后，抽 `PostprocessTemplateService` / `PostprocessPlanVersionService`；
5. 管理台路由继续膨胀时，再按 auth / callers / tasks / settings / postprocess 拆 router。

## 不在本任务范围

- 不立即修改业务代码；
- 不改变 REST / MCP 对外契约；
- 不引入新的数据库表；
- 不调整 Docker 镜像构建；
- 不把本文档当作已经完成的产品功能说明。

本任务只保存分析结论和优化计划，供后续拆分实际开发任务使用。

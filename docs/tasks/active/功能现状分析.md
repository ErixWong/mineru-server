# MCP Server 功能现状分析

**检查时间**: 2026-05-09
**用户需求**: /mcp 和 /api 功能一致，传入 base64 文件，放入队列解析

---

## 1. 用户需求理解

### 1.1 核心需求

**功能一致性**：
- `/mcp` (MCP Tools) 和 `/api` (REST API) 功能相同

**输入方式**：
- ✅ 接收 base64 文件内容（不是本地文件路径）
- ✅ 接收文件名（可选）

**处理流程**：
1. 接收 base64 文件 → 解码保存临时文件
2. 放入解析队列 → 异步处理
3. 返回 task_id → 用户轮询状态
4. 返回状态/结果 → Markdown + 图片

---

## 2. 当前实现对比

### 2.1 MCP Tools（/mcp）

**当前实现**：

| Tool | 输入 | 功能 | 状态 |
|------|------|------|------|
| `parse_pdf` | ❌ `file_path`（本地路径） | 同步解析，返回结果 | ⚠️ 需改进 |
| `submit_task` | ❌ `file_path`（本地路径） | 异步提交，返回 task_id | ⚠️ 需改进 |
| `get_task` | `task_id` | 查询状态和 Markdown | ✅ 已有 |
| `get_images` | `task_id` | 获取图片（Base64） | ✅ 已有 |
| `list_backends` | 无 | 列出后端 | ✅ 已有 |
| `health_check` | 无 | 健康检查 | ✅ 已有 |

**问题**：
- ❌ 只接收 `file_path`（本地文件路径）
- ❌ 不支持 base64 文件内容
- ❌ 不支持文件上传（bytes）
- ⚠️ MCP Client（Claude Desktop）无法直接传入本地路径

---

| Endpoint | 输入 | 功能 | 状态 |

**问题**：
- ❌ 只接收 `file_path`（JSON body）
- ❌ 不支持 base64 文件内容
- ❌ 不支持 multipart/form-data 上传
- ⚠️ 用户需先上传文件到服务器，再传入路径

| Endpoint | 输入 | 功能 | 状态 |

**优势**：
- ✅ 支持文件上传（`UploadFile`）
- ✅ multipart/form-data 格式
- ✅ 标准文件上传流程

## 3. 关键差异总结

### 3.1 输入方式差异

| API | 输入方式 | 优势 | 劣势 |
|-----|---------|------|------|
| MCP Tools | `file_path`（本地路径） | - | ❌ MCP Client 无法传入本地路径 |
| REST API | `file_path`（JSON body） | - | ❌ 用户需先上传文件 |
| MinerU 原生 | `UploadFile`（multipart） | ✅ 标准上传 | - |

**结论**：
- ❌ MCP Server API 输入方式不符合用户需求
- ✅ MinerU 原生 API 输入方式正确

---

### 3.2 文件处理流程差异

**MCP Server 当前流程**：
```
用户 → 提供 file_path
     → mineru_client.py 读取本地文件
     → HTTP POST MinerU /file_parse（上传文件）
     → MinerU 解析
     → 返回结果
```

**问题**：
- ⚠️ 绕了一圈：MCP Server 先读取本地文件，再上传到 MinerU
- ⚠️ 要求文件在 MCP Server 可访问的路径

**正确流程（用户需求）**：
```
用户 → 提供 base64 文件内容
     → MCP Server 解码，保存临时文件
     → 放入队列（异步）
     → 返回 task_id
     → 用户轮询 /tasks/{id}
     → 返回状态/结果
```

## 5. 改进方案

### 5.1 方案一：添加 base64 输入（推荐 ✅）

**实现步骤**：

1. **修改 MCP Tools 参数**：
```python
@mcp.tool()
async def parse_pdf(
    file_base64: str,  # ✅ 新增：base64 文件内容
    file_name: Optional[str] = None,  # ✅ 新增：文件名
    backend: str = "hybrid-http-client",
    lang: str = "ch",
    ...
) -> dict:
    """Parse PDF from base64 content"""
    # 解码 base64
    file_bytes = base64.b64decode(file_base64)
    
    # 保存临时文件
    temp_file = Path(f"/tmp/{uuid.uuid4()}.pdf")
    temp_file.write_bytes(file_bytes)
    
    # 提交到 MinerU 队列
    task_id = await client.submit_task(
        file_path=str(temp_file),
        backend=backend,
        ...
    )
    
    return {"task_id": task_id, "status": "pending"}
```

2. **修改 REST API 参数**：
```python
@app.post("/parse")
async def parse_pdf_sync(request: Request):
    body = await request.json()
    
    # ✅ 支持两种输入方式
    file_base64 = body.get("file_base64")
    file_path = body.get("file_path")
    
    if file_base64:
        # 解码 base64，保存临时文件
        file_bytes = base64.b64decode(file_base64)
        temp_file = Path(f"/tmp/{uuid.uuid4()}.pdf")
        temp_file.write_bytes(file_bytes)
        validated_path = temp_file
    elif file_path:
        # 使用本地文件路径（向后兼容）
        validated_path = validate_file_path(file_path)
    else:
        raise HTTPException(400, "file_base64 or file_path required")
    
    # 提交到 MinerU
    result = await client.parse_pdf_sync(
        file_path=str(validated_path),
        ...
    )
    return result
```
